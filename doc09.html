职场小助手 RAG 产品方案

职场小助手 RAG 产品方案与评测说明

本文档基于已上线的“职场小助手”Agent（基于FastGPT平台搭建，覆盖劳动法问答、职场维权等场景），按照 PRD结构撰写。

一、背景与目标

1.1 要解决的业务问题

职场新人（尤其是应届毕业生）普遍缺乏劳动法常识，面临以下典型困境：

  1. 信息不对称：不知道试用期辞退需要“不符合录用条件”的法定依据，被公司一句“能力不行”就打发了
  2. 检索成本高：《劳动合同法》全文近万字，普通用户难以快速定位到与自己处境相关的条款
  3. 缺乏行动指引：即便查到了法条，也不知道“下一步该怎么做”、“话术怎么说”

1.2 为什么用AI而不是规则/人工

方案

劣势

规则引擎（关键词匹配）

用户提问方式千变万化（“试用期被开”、“试用期辞退”、“试用期不让干了”），无法穷举所有问法

纯人工客服

成本高、无法7×24小时响应

传统搜索引擎

返回大量网页，用户仍需自行筛选、阅读、理解

纯大模型（无RAG）

会编造不存在的法条（幻觉），风险极高

RAG方案的核心价值：让AI“照着权威资料念”，既保留了大模型的理解和表达能力，又通过知识库约束了回答边界。

3.2 评测集

来源：

  1. 从真实用户提问中抽取样本（覆盖试用期、加班费、离职赔偿、合同签署等场景）
  2. 手动构造边界测试用例（模糊问法、超纲问题、多轮对话）
  3. 规模：当前评测集约20个典型问题，计划扩展至50+
  4. 标注标准：每个测试问题预先标注“正确答案要点”（法条依据+核心建议），用于判断AI回答是否达标

3.2.2更新机制：每次新增知识库内容后，用评测集全量回归测试，确保不引入新的错误

4. 能力边界与不承诺清单

4.1 明确支持的场景

  1. 劳动法相关问题（试用期、劳动合同、加班费、辞退赔偿、社保公积金等）
  2. 基于已收录法条和案例的维权建议
  3. 提供可直接使用的沟通话术

4.2 明确不支持的场景

  1. 非劳动法领域（婚姻、房产、刑事等）
  2. 代替专业律师出具法律意见
  3. 涉及具体金额计算（如“我该拿多少赔偿”需要结合个人工资、工龄等，无法精确计算）
  4. 实时政策查询（法律法规更新后需人工补充知识库）

4.3 已知失败模式

  1. 用户问法极度口语化且省略关键信息（如“那个钱”），可能导致检索不到
  2. 多轮对话中话题切换，上下文补全可能产生偏差
  3. 知识库未覆盖的新法规出台后，回答可能滞后

4.4 不承诺的效果

  1. 不承诺100%准确（法律解读存在专业分歧）
  2. 不承诺替代专业法律咨询
  3. 不承诺实时更新（知识库更新依赖人工维护）

4.5 高风险场景的强制阻断规则

  1. 涉及“怎么钻法律空子”“怎么伪造证据”等违规问题 → 直接拒绝回答
  2. 涉及“人命关天”的紧急法律问题（如“被拘留了怎么办”）→ 强制引导“请立即联系律师或报警”

5. 数据需求与回流设计

5.1 冷启动数据来源

  1. 《中华人民共和国劳动合同法》全文（政府官网手动搬运）
  2. 权威劳动法解读文章（筛选后人工清洗）
  3. 真实职场案例（脱敏处理，转化为“场景-依据-建议”结构）

关键原则：所有数据必须人工复核来源，严禁AI自动生成法条

5.2 线上数据回流机制

5.2.1埋点：

  1. 记录每次问答的完整对话（用户问题、AI回答、检索到的知识片段）
  2. 记录用户是否点击“引用来源”查看原文（可作为“是否满意”的间接信号）

5.2.2Bad Case收集：

  1. 自动标记：检索相关度低于阈值但仍生成回答的（可能幻觉）
  2. 人工标记：用户反馈“回答不对”或“没帮到我”

5.2.3标注分发：

  1. 将Bad Case按问题类型分类（召回失败/生成幻觉/格式错误等）
  2. 每周集中review，判断是否需要补充知识库、调整检索参数或修改Prompt

5.3 数据合规红线

  1. 知识库中不含任何个人隐私数据
  2. 不含任何诱导违法、违规的内容
  3. 回答末尾强制附带免责声明

7. 兜底与风险

7.1 置信度分级与降级链路

用户提问

↓

检索相关度 ≥ 0.1？ ──否──→ 回复：“该问题暂未收录，建议咨询专业律师或HR”

↓ 是

检索相关度 ≥ 0.5？ ──否──→ 回复：“以下内容仅供参考，建议进一步核实”

↓ 是

正常输出三段式回答（末尾强制带免责声明）

7.2 人工介入触发条件

  1. 用户连续3次追问“你确定吗？”或“你懂不懂？”→ 引导“建议咨询专业律师”
  2. 用户提到“急”“马上”“今天就要”→ 引导“紧急情况请拨打12333（劳动保障热线）”
  3. 用户问到超出边界的内容 → 强制拒绝并给出替代建议

8. 上线计划与灰度策略

8.1 当前状态

  1. ✅ 已完成：知识库搭建（《劳动合同法》核心条款已入库）
  2. ✅ 已完成：检索参数调优（混合检索 + 最低相关度0.1 + 重排模型）
  3. ✅ 已完成：Prompt工程（三段式输出 + 强制基于知识库 + 免责声明）
  4. ✅ 已完成：分享链接发布（免登录，限积分100）

8.2 灰度策略

  1. 灰度范围：先分享给5-10位同学/朋友试用
  2. 观察周期：1-2周，收集反馈和Bad Case
  3. 回滚条件：若出现3次以上“引用错误法条”的严重幻觉，立即下线排查

9. 后续迭代计划

9.1 短期（1个月内）

  1. 扩充知识库：增加“加班费计算”“年休假”“工伤认定”等高频场景
  2. 优化评测集：从20个问题扩展至50+，覆盖更多边界情况
  3. 收集首批用户反馈，修复已知Bad Case

9.2 中期（3个月内）

  1. 引入“数据飞轮”：将线上Bad Case持续转化为新的知识片段或测试用例
  2. 增加“置信度打分”功能：当检索相关度偏低时，主动提示用户“该回答仅供参考”
  3. 探索接入更权威的实时数据源（如各地人社局的公开数据）

9.3 数据飞轮设计

线上对话 → 自动/人工标记Bad Case → 分类归因 → 定向优化
