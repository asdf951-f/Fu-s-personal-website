一、项目简介

1.1 项目定位

「触感·她界」是一套面向视障女性的公共私密空间全程陪伴系统，帮助视障女性（含全盲、低视力、视野缺陷、对比敏感度下降等）在公共卫生间、母婴室、更衣室等空间中完成「寻找 — 到达 — 进入 — 使用 — 求助 — 离开 — 反馈」的完整闭环。

系统以 「小触感」智能体 为语音交互中枢（基于阿里云百炼平台搭建），通过 NFC 可信锚点、空间语义图、情感化 AI 语音、AI 视觉识别、多模态无障碍交互、分级求助响应与共治机制，让视障女性从「被设计者」变成「联合设计者」。

1.2 一句话定位

让视障女性在公共私密空间中 「找得到、进得去、用得安心、出得安全、看不清时识得出」。

1.3 核心价值

  • 让视障女性不再因「看不见」而恐惧进入陌生卫生间；
  • 让视障女性不再因「说不清」而在紧急时刻孤立无援；
  • 让视障女性不再因「被忽视」而长期忍受公共设施的不便与不安；
  • 让每一次求助都 有人接单、有人到达、有闭环反馈；
  • 让视障女性面对「看不清」的未知物品时，不再靠猜、不再靠问，AI 替物品开口说话。

1.5 与现有产品的本质区别

别人做「帮你看见世界」，我们做「帮你安全使用私密空间」。相较 Be My Eyes（视障者 + 志愿者视频）、通用地图 App 等，触感·她界具备 女性专属视角、物件级导航、求助闭环响应、零摄像头隐私保护、离线优先 五大差异化能力。

二、技术架构

2.1 整体分层

系统采用「低成本感知层 + 空间语义数据层 + AI 智能体层 + 闭环响应层」的分层架构：

  • 感知层：NFC 无源贴片（NTAG216）、触感面板（盲文 + 凸纹标识）、可选蓝牙 Beacon；无需布线、无需电池，单设施部署约 41 元。
  • 数据层：四级空间语义模型（场所 → 设施 → 功能区 → 关键物件）。每件物件含「方位 / 高度 / 触感特征 / 语音描述」，支持 AI 生成自然语言导航与可信度评分，零摄像头、零隐私风险。
  • AI 层：基于阿里云百炼平台搭建「小触感」智能体（Qwen-Plus-Latest），承载紧急求助、智能导航、物品识别、反馈共治、话术切换；AI 视觉识别复用通义千问 VL 多模态模型，图像本地处理、即删、不上传。
  • 交互层：自建无障碍浏览（自研焦点树 + 手势引擎 + TTS 语音合成 + 震动反馈），零第三方库、轻量可控，不依赖系统读屏。
  • 闭环响应层：用户端 + 响应者端 + 管理端三端协同，求助分级（L1–L4）+ 超时自动升级（30 / 60 / 120 / 180 秒）。

2.4 离线优先与零摄像头

  • 离线优先：本地设施包、本地预生成语音包（100+ 条离线语音）、本地空间图、NFC 读取均不依赖网络；网络恢复后自动同步。无网状态下核心功能 100% 可用。
  • 零摄像头：设施端不装摄像头；AI 视觉识别遵循「三不原则」——不识别血迹、不判断经血量、不推断生理期阶段；图像本地处理、即删、不上传，与「零摄像头」构成双重隐私防线。

3.2 八大核心功能板块

  1. 智能推荐：综合距离、可信度、无障碍匹配、实时状态推荐设施；核心创新是「设施可信度评分」（核验时效 / 数据来源 / 用户反馈 / 实时状态）。
  2. 三层导航：室外导航（百度地图 MCP，米级）→ 场所内导航（Beacon + 空间语义图，3–5 米）→ 精细导航（NFC + 触感地标，物件级）；关键创新是「入口画像」（门推/拉、把手左右、高度、门槛、NFC 位置）。
  3. 全流程陪伴（六阶段状态机）：寻找 → 到达入口 → 进入空间 → 使用设施 → 清洁整理 → 安全离开；每阶段自动切换、对应焦点管理、可随时取消、隐私模式自动降音量。
  4. 生理期安心模式：设施优先推荐、导览优先级调整、含蓄话术、凸点识别标准（日用 = 3 圆点，夜用 = 方块）、应急取用、AI 生理期用品识别（通义千问 VL，含品牌识别增强）。
  5. 守护中心（核心安全功能）：多种触发（大按钮长按 1.5 秒 / 静默模式 / 语音暗号 / 守护超时）、求助分级（L1–L4）、响应闭环（接单 → 到达 → 处理 → 确认安全 → 归档）、超时自动升级（30/60/120/180 秒逐级通知）、守护模式、静默求助与伪装来电。
  6. 反馈与共治：快速反馈（5 表情 + 问题标签）、工单闭环、话术投票、触感标准共创、一票否决、数据信托。
  7. 核心辅助设置：读屏优化（自研焦点树，左右滑切焦点 + 双击触发 + 15ms 震动 + 金色焦点环 + 语音三重确认）、视觉辅助（高对比/色盲友好/护眼暖色/阅读标尺/纯净背景）、对比度三档。
  8. AI Agent 智能体层（小触感）：基于百炼平台，4 个 Skill 覆盖 12+ 核心功能（紧急求助 / 智能导航 / 物品识别 / 反馈共治 / 话术切换），5–8 轮短期记忆保障多轮对话；闺蜜风 / 简洁风可切换。回复通过 useTTS 以中文女声朗读，每条 AI 气泡附带「🔊 重新朗读」按钮便于演示重播（详见第八章 8.1）。

五、应用价值与真实场景效果

5.1 一个真实场景

小林，28 岁，先天视障，在公司做客服。中午她需要去商场三层的卫生间。
以前她要在门口站 5 分钟，等好心人确认「这是女厕所、里面没人、地面不滑」。
现在她打开触感·她界：手机告诉她「无障碍卫生间在您右前方 45 米，最近刚打扫过，地面干燥」。
她沿右侧墙面走，到达门口，手机靠近 NFC 贴片自动播报「门是自动门，入口宽 90 厘米。进门左侧是无障碍厕位，门锁在右手边，向下按压」。她开启「安静守护」，系统安静陪着她。使用完毕，她说「我完成了」，系统提示「出口在您右后方，我陪您到门口」。离开前她摸出一包未拆封卫生巾，记不清日用还是夜用——拍照后系统播报「这是日用卫生巾，长度 240mm，带易撕口」。整个过程，没有求助陌生人，没有尴尬，没有恐惧。

  3. 接入 Serverless 后端（进阶）：将 vite.config.ts 中的 /api/ai/chat 代理抽成 Vercel Function / Cloudflare Worker / Railway Node 等后端函数，静态前端 + 一个后端接口即可实现真实 Agent，且不暴露 API Key。

八、已知限制与后续迭代

本章汇总当前版本已知平台限制与后续可选方向，供开发者在此基础上继续迭代。其中 8.1 为本期重点迭代点。

8.1 语音播报（TTS）的浏览器兼容性【迭代点】

现象

小触感 AI 回复后本应通过 Web Speech API 朗读。实测：Edge 浏览器可正常女声播报，但 Chrome（桌面未装中文语音包 / 安卓 Chrome）下静默无声音。

根因（已定位，非代码缺陷）

  • Web Speech API（speechSynthesis）的中文语音来自系统离线语音；
  • Edge 自带微软云端神经中文语音，不依赖系统，开箱即响；
  • Chrome 依赖操作系统语音（Windows SAPI / macOS 系统语音），若系统未安装中文（简体）语音包，getVoices() 无 zh-CN 语音，播报静默；
  • 安卓 Chrome 的 speechSynthesis 存在长期未修复的兼容缺陷，基本不发音。

已采取的措施（代码层，v2 已落地）

  • 统一接入 useTTS hook：自动优选中文女声、支持语速/音调/隐私模式、Capacitor 离线包；
  • AI 回复气泡新增「🔊 重新朗读」按钮，便于演示时手动重播；
  • 在用户手势同步栈内预热语音引擎，规避 iOS Safari 自动播放拦截；
  • useTTS 内置 2 秒超时检测：若 speak() 调用后未触发 onstart，自动将能力标记为 unavailable 供 UI 诊断（可据此给用户提示）；
  • 修复了此前「speak() 后立即 cancel() 导致 Chrome 引擎卡死」的实现缺陷。

后续迭代方向（请开发者在此修改 / 选型）

  1. 引导安装系统中文语音（低成本）：在文档/界面提示用户在 Windows「设置 → 语言 → 中文(简体) → 语音」中下载「Microsoft 晓妍 / 云希」等中文语音包，装完后 Chrome 即可发声。
  2. 演示录制统一使用 Edge（零成本）：当前 v2 线上实例在 Edge 下语音播报已完全可用，适合直接录展示视频。
  3. 接入云端 TTS（跨浏览器最稳，推荐研究中）：用阿里云 DashScope 语音合成等云端服务，前端请求返回 mp3 后用 <audio> 播放，任何浏览器 / 安卓均稳响，彻底脱离系统语音。需在前端注入 VITE_DASHSCOPE_API_KEY（与现有 VisionService 同源，已编译进公开 JS，演示可用），并新增一个 TTS 适配层替换 WebSpeechAdapter。
  4. 深化 Capacitor 离线语音包（APK 路线）：将动态 AI 回复也接入 APK 内预置的女声 mp3 方案（当前离线包仅用于 Capacitor 环境的"静态话术"精确匹配，动态回复仍走 Web Speech），完全绕过系统 TTS。

备注：仓库已内置 100+ 条离线语音包，但仅用于 Capacitor APK 环境的静态话术精确匹配；动态 AI 回复目前仍走 Web Speech API，故浏览器端仍需上述处理。若选择方向 3，建议将 TTS 抽象为独立 TTSProvider 接口，使「Web Speech / 云端 TTS / 离线包」三者可热插拔。

8.2 其他已知限制

  • 静态托管下「小触感」AI 对话降级为模拟回复（见第七节），真实语义理解需 Node 服务或后端函数；
  • Web 端 NFC 为手动编号降级，真实 NFC 近场感应需 Capacitor 原生环境（见第六章移动端部署）；
  • 实时求助 / 响应者端 / 管理端为前端模拟，真实分级响应与超时升级待后端对接；
  • 百度地图 MCP 为 offline 降级，真实米级导航对接位置已在 vite.config.ts 预留 reserved slot。

8.3 迭代建议清单（供评审/贡献者参考）

  • TTS：评估并接入云端 TTS，消除 Chrome / 安卓浏览器的语音兼容问题（8.1 方向 3）；
  • NFC：提供 Web 端一次性手动扫描的明确 UI 引导，减少"误以为坏了"的困惑；
  • Agent：提供一键 Serverless 后端模板，让静态托管也能启用真实大模型；
  • 文档：补充无障碍手势操作速查表与读屏兼容性说明。
